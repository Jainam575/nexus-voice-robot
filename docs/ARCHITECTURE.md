# 🏗️ Architecture

## Two builds of the same robot

- **Package form** — `nexus/` (23 modules) + `run_nexus.py`. For
  development and running the test suite.
- **Single file** — `nexus_all_in_one.py`, generated by
  `scripts/build_combined.py`. One file to copy to the Pi. Identical
  behaviour, verified by the same 302 tests run against the combined file.

The build script concatenates modules, dedupes imports, and converts the
package `__init__` exports into plain statements. Import paths are
namespace-preserving, so all internal cross-module references keep working.

## Module map

```
nexus/
├── main.py             Voice loop, wake word, command routing (priority
│                       ladder: safety → sleep → navigation → movement →
│                       special → vision → LLM chat)
├── config.py           All env vars and constants — every setting in one
│                       file, all overridable without code changes
├── stt.py              Sarvam STT + circuit breaker (3 failures → open 60 s
│                       → half-open probe) + retry with backoff
├── tts.py              Sarvam TTS (bulbul) + script-based language
│                       auto-detection (Gujarati/Devanagari → gu-IN/hi-IN)
├── audio.py            arecord capture, silence detection, aplay playback,
│                       AudioManager singleton
├── camera.py           picamera2 wrapper (numpy 1.x compatible, correct
│                       RGB/BGR handling, thread-safe)
├── vision.py           Unified describe() with 3 modes: offline TFLite
│                       (SSD-MobileNet COCO), cloud VLM (OpenAI-compatible
│                       API), auto. Atomic JSON caches, TTL, vision log
├── navigation.py       Vision-guided movement: target search (offline
│                       detector → cloud VLM direction query → turn toward),
│                       step approach with obstacle checks
├── face_recognition.py Haar detection (4 cascades) + LBPH training,
│                       enrollment with quality control, 0600-permission
│                       storage, multi-frame consensus recognition
├── motor.py            GPIO abstraction (works without RPi.GPIO for tests),
│                       blocking movement API, watchdog, safety stop,
│                       collision interrupt, PWM ramping
├── command_parser.py   Movement parsing (words/digits, seconds/steps)
├── face_display.py     Pygame face: moods, states, camera preview,
│                       VAD-talking animation
├── mood.py             Mood engine with touch/decay
├── memory.py           Persistent memory (atomic JSON writes)
├── weather.py         Open-Meteo + geocoding + WMO code mapping
├── news.py             Google News RSS
├── games.py            Voice games (rock-paper-scissors, trivia)
├── safety.py           Safety state machine
├── safety_listener.py  Background listener for urgent stop
├── collision.py        Distance sensor abstraction
├── latency.py          Latency budgets/logging
└── shutdown.py         Clean shutdown handling
```

## Request lifecycle

1. `audio.record_until_silence()` → WAV
2. `stt.transcribe()` → text (circuit breaker guards this)
3. `main` matches the text against the priority ladder
4. A subsystem executes (motor / vision / navigation / face / weather /
   news / games / memory / mood)
5. Otherwise → `stt`→`chat` with session history → reply
6. `tts.speak()` → language auto-detected from script → audio stream →
   `aplay`

## Testing

302 tests, all hardware-mocked (GPIO, camera, audio, network) — the suite
runs on any machine:

```bash
pytest tests/ -q
```

Notable test areas: parser grammar, safety state transitions, motor
blocking/watchdog semantics, navigation math, vision validation, games
scoring, memory persistence, mood decay, and the round-2 fix regression
suite.
